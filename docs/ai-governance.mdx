AI Governance puts a policy checkpoint between your [Mezmo AURA](../aura/index) agents and the tools they call. Before a tool call runs, AURA asks Mezmo whether the call can proceed. Mezmo checks the call against the policy assigned to that agent and answers in one of three ways: allow the call, deny it, or hold it until a person approves it. Use AI Governance to let agents act on their own where it's safe, keep a person in the loop for risky actions, and keep a record of every decision.

This page explains how AI Governance works and how to set it up. Each part has its own page, listed in [AI Governance Pages](#ai-governance-pages). For how approval gates work inside AURA itself, see [Human-in-the-Loop Approval Gates](../aura/hitl).

<Note>
AI Governance is available when it is enabled for your account. If you don't see **AI Governance** in the left navigation of the Mezmo web app, contact Mezmo, or ask your account admin about your permissions.
</Note>

## How AI Governance Works

AI Governance connects four parts:

- **Agents.** An agent is an AURA instance registered to your Mezmo account. Each agent signs in with its own service account, which tells Mezmo which agent is asking. See [AI Governance Agents](./governance-agents).
- **Policies.** A policy is a versioned set of rules. Each rule matches tool calls by the tool's namespace, the tool's name, or the arguments the agent passed, and gives an outcome: **Allow**, **Require Approval**, or **Deny**. A call that no rule matches gets the policy's fallthrough outcome. See [AI Governance Policies](./governance-policies).
- **Workflows.** Every request an agent sends is recorded as a workflow, with its tool calls and the decision for each one. A workflow that needs a person stays **Pending** until someone approves or denies it, or until it expires. See [AI Governance Workflows](./governance-workflows).
- **Approvers.** A policy can name an approving role. Only members of that role can approve or deny the calls that the policy holds. Approvers can decide in the Mezmo web app or from a notice in Slack. See [Approve AI Governance Requests in Slack](./governance-slack-approvals).

When an agent wants to run a tool call:

1. AURA sends the call to Mezmo before running it.
2. Mezmo finds the agent from the service account credentials and evaluates the call against the agent's policy.
3. When several rules match, the most restrictive outcome wins. **Deny** outranks **Require Approval**, which outranks **Allow**. A request that holds several tool calls gets the most restrictive outcome of all its calls.
4. An allowed request runs right away, and a denied request is refused with the rule's code and message. A request that requires approval waits for an approver. If nobody decides within the approval window, which is 15 minutes, the workflow expires and the agent treats it as denied.

Mezmo records the decision as a workflow in every case, so you can review what each agent asked to do and how each request was decided.

<Warning title="Agents without a policy are refused">
If an agent has no policy assigned, Mezmo refuses every tool call it sends. Assign a policy to each agent before you route its tool calls to Mezmo.
</Warning>

## Set Up AI Governance

Set up AI Governance in this order, so that each agent has a policy as soon as it starts sending tool calls.

1. [Create a policy](./governance-policies#create-a-policy) with rules for the tools your agents use, and choose its fallthrough outcome.
2. Recommended. On the policy's **Approvers** step, [assign an approving role](./governance-policies#approvers), and add Slack channels that should receive approval notices.
3. Recommended. [Evaluate the policy](./governance-policy-testing#evaluate-a-policy) with sample tool calls to confirm that its rules decide as you expect.
4. [Register an agent](./governance-agents#register-an-agent), choose its service account, and assign the policy.
5. [Connect the agent to AURA](./governance-agents#connect-the-agent-to-aura) by adding the configuration from the registration wizard to the agent's `config.toml`.
6. [Review workflows](./governance-workflows) as the agent works, and approve or deny the requests that the policy holds.

## Find AI Governance in Mezmo

In the Mezmo web app, select **AI Governance** in the left navigation. The **Governance** sidebar lists the pages you have access to:

| Page | What you do there |
| ---- | ---- |
| **Overview** | Monitor decisions, pending approvals, and agent and policy health. See [AI Governance Overview Dashboard](./governance-overview-dashboard). |
| **Workflows** | Review requests and approve or deny the ones waiting on a person. See [AI Governance Workflows](./governance-workflows). |
| **Policies** | Create, change, evaluate, and test policies. See [AI Governance Policies](./governance-policies). |
| **Test Cases** | Keep a library of saved test cases to use with any policy. See [Evaluate and Test AI Governance Policies](./governance-policy-testing). |
| **Agents** | Register AURA agents and assign their policies. See [AI Governance Agents](./governance-agents). |

When requests are waiting for approval, a count appears on the **AI Governance** navigation item. Hover over it to see the newest pending workflows.

Selecting **AI Governance** opens the first page you can use: **Overview**, then **Policies**, then **Agents**.

## Permissions

Each AI Governance page needs a permission on your role. Account admins set permissions on a role's **Permissions** tab under **Settings** > **Organization** > **Roles**. Levels are cumulative: **Manage** includes **Write**, and **Write** includes **Read**. See [Role-Based Access Control](./rbac).

| Permission | Level | What it lets you do |
| ---- | ---- | ---- |
| `workflow` | Read | View the **Overview** dashboard, the **Workflows** list, and workflow details. |
| `workflow` | Write | Approve or deny pending workflows, in the web app or from Slack. |
| `policy` | Read | View and evaluate policies, and view test suites and the **Test Cases** library. |
| `policy` | Write | Create policies, change them through drafts, fork and revert revisions, and edit and run test suites and test cases. |
| `policy` | Manage | Delete policies. |
| `agent` | Read | View the **AURA Agents** list. |
| `agent` | Write | Register and edit agents. Choosing or creating the agent's service account also needs `service_account` permissions. |
| `agent` | Manage | Delete agents. |

Some features also need other permissions:

- To see or assign a policy's approving role, you need `role` Read. To create an approving role from the policy wizard, you need `role` Write.
- To add Slack notification channels to a policy, you need `role` Read and `integration` Manage.

If a policy names an approving role, you also need to belong to that role to approve or deny its workflows.

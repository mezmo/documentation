Example TOML configurations and advanced quickstarts for AURA agents.

<Note>**New to AURA?** Start with the [Quickstart](/aura/quickstart). It installs AURA, generates a config, and connects it to your tools. Come back here when you're ready to customize.</Note>

## Reference Configuration

[`reference.toml`](https://github.com/mezmo/aura/blob/main/examples/reference.toml) is the annotated config covering the core sections (MCP servers, vector stores, tools, agent, LLM). Use it as a starting point:

```bash
export OPENAI_API_KEY="sk-..."
cp examples/reference.toml config.toml
# Edit config.toml with your settings
cargo run --bin aura -- webserver
```

For orchestration, HITL, scratchpad, skills, client tools, and reasoning parameters, start from the matching file under [Feature Examples](#feature-examples) instead; each one is a complete, loadable config for that feature.

If encountering issues and more verbose debugging output is necessary, add the `--verbose` flag for the running binary:
```bash
export OPENAI_API_KEY="sk-..."
CONFIG_PATH=examples/minimal/openai.toml cargo run --bin aura -- webserver --verbose
```

### Serving Multiple Agents

Point `CONFIG_PATH` at a directory to serve every `.toml` file in it as a selectable agent. [`examples/multi-agent/`](https://github.com/mezmo/aura/tree/main/examples/multi-agent) holds three agents and a README:

```bash
export OPENAI_API_KEY="sk-..."
CONFIG_PATH=examples/multi-agent/ DEFAULT_AGENT=sre cargo run --bin aura -- webserver
curl -s localhost:8080/v1/models | jq '.data[].id'
```

Clients discover agents via `GET /v1/models` and select one with the `model` field in chat requests. Each agent is identified by its `alias` (if set) or `name`, and those ids must be unique across the directory. `DEFAULT_AGENT` names the agent used when a request omits `model`; without it, a multi-agent server returns 400 for such requests. An agent with `hidden = true` stays callable by id but is left out of `/v1/models`.

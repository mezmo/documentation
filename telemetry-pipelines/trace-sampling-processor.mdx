## Description

Performs sampling of traces per a given rate using the Trace ID as the unique identifier. If a trace is rate selected, all spans of the trace are output.

<Note>
This is an experimental feature that is still in development. For access to this feature, reach out to your Customer Support Manager or support@mezmo.com.
</Note>

## Use

Two well-known optimization techniques for traces are Deterministic Sampling (Head sampling) and more advanced Tail-based sampling. While head-based sampling will treat all traces equally and sample randomly, Tail-based sampling enables you to sample at different rates for traces you consider to have different levels of importance, based on attributes that traces contain, for example prioritizing traces with errors, latency, or traces that exceed certain performance thresholds. This is implemented in this Processor through conditional statements to define the trace. 

<Note>
This Processor supports sampling of [OTel traces only](https://opentelemetry.io/docs/concepts/signals/traces/).
</Note>

## Configuration

| Option | Description | Example | 
| ---- | ---- | ---- | 
| Sample Type | The type of sampling to invoke. | `head`  `tail` | 
| Trace ID field | The field to use as the identifier of a trace. Defaults to `.record.traceId`. | `.record.traceId` | 
| Rate | The rate at which to sample traces. For example, `10` means 1 out of every 10 traces will be sampled. | `10` | 
| Parent Span ID (Tail Only) | The field to use as the parent span identifier. Defaults to `.record.parentSpanId`. | `.record.parentSpanId` | 
| Conditional (Tail Only) | Used in conjunction with Rate, a conditional statement to define the field for sampling |  | 

<Note>
By default, the Trace ID and Parent Span ID fields point to `.record.traceId` and `.record.parentSpanId`. These paths match the structure produced by the combined [OpenTelemetry Source](/telemetry-pipelines/open-telemetry-source), which nests `traceId` and `parentSpanId` under a `.record` property, so the Processor works with that Source without extra setup. If your traces store these values elsewhere, set each field to the path where the value lives.
</Note>

## How tail sampling closes a trace

In `tail` mode, the Processor decides a trace when the head span of the trace arrives. The head span is the span that has no Parent Span ID. The Processor does not wait for a timer, a maximum trace duration, or a span count before it decides.

The Processor handles a trace in this order:

1. A span that has a Parent Span ID and arrives before the head span is held. The Processor does not output it yet.
2. When the head span arrives, the Processor checks it against the conditionals. If there is more than one conditional, the first one that matches is used. Only the head span is checked, so the conditional must use fields that the head span carries.
3. The Processor applies the Rate of the matching conditional. A Rate of `1` keeps every matching trace. A Rate of `10` keeps the first matching trace and then 1 of every 10 matching traces. A trace that matches no conditional is not kept.
4. If the trace is kept, the Processor outputs the head span and all the held spans together. If the trace is not kept, the Processor discards the held spans.

The Processor remembers the decision for the trace. A span of the same trace that arrives after the decision is not evaluated again. The Processor outputs it at once if the trace was kept, and drops it if the trace was not kept. This applies whether or not the span has a Parent Span ID.

### Time limit on a decision

The Processor keeps the decision, and any held spans, for at least 5 minutes. The time limit is not an option of this Processor. The storage layer removes expired records on a best-effort basis, so a record can outlast the limit.

After the limit passes, the Processor no longer knows the trace:

- A late span that has a Parent Span ID is held again. The Processor does not output it unless a head span for the same trace arrives.
- A late span that has no Parent Span ID is treated as a new head span. The Processor makes a new decision for the trace, and applies the Rate again.

Keep these cases in mind when you design a conditional:

- A trace whose head span never arrives is never output. Its held spans expire.
- A span without a trace ID is dropped, and the Processor records a warning.
- An event whose message is not an object is dropped, and the Processor records a warning.

## Examples

Examples of OTEL traces that can be sampled using the Processor.

#### The head of a trace indicated by a null `parent_id` field

```json
{
  "name": "hello",
  "context": {
    "traceid": "5b8aa5a2d2c872e8321cf37308d69df2",
    "spanid": "051581bf3cb55c13"
  },
  "parent_id": null,
  "start_time": "2022-04-29T18:52:58.114201Z",
  "end_time": "2022-04-29T18:52:58.114687Z",
  "attributes": {
    "http.route": "some_route1"
  },
  "events": [
    {
      "name": "Guten Tag!",
      "timestamp": "2022-04-29T18:52:58.114561Z",
      "attributes": {
        "event_attributes": 1
      }
    }
  ]
}

```

#### A related span under the same trace, indicated by the `parent_id` matching the `span_id` of the head

```json
{
  "name": "hello-salutations",
  "context": {
    "traceid": "5b8aa5a2d2c872e8321cf37308d69df2",
    "spanid": "93564f51e1abe1c2"
  },
  "parent_id": "051581bf3cb55c13",
  "start_time": "2022-04-29T18:52:58.114492Z",
  "end_time": "2022-04-29T18:52:58.114631Z",
  "attributes": {
    "http.route": "some_route3"
  },
  "events": [
    {
      "name": "hey there!",
      "timestamp": "2022-04-29T18:52:58.114561Z",

      }
    }
  ]
}

```

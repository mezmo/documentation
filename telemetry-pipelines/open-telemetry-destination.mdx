## Description

You can send your logs, metrics and traces to any destination that accepts data using the OpenTelemetry protocol, for example Grafana, TelemetryHub, or New Relic.

## Supported Events

The Destination accepts these events:

| Signal | Accepted events |
| ---- | ---- |
| Logs | Events from the **Logs** output of the [OpenTelemetry source](./open-telemetry-source), or from the deprecated **OpenTelemetry Logs** source |
| Traces | Events from the **Traces** output of the OpenTelemetry source, or from the deprecated **OpenTelemetry Traces** source |
| Metrics | Events from the **Metrics** output of the OpenTelemetry source, or Mezmo metric events |

A span from the OpenTelemetry source must have a valid `traceId` and `spanId`. The Destination doesn't send a span whose ID is missing or invalid, and reports an error that names the field. The rest of the batch is still sent.

### How Metrics Are Sent

The Destination converts each [Mezmo metric](./metric-data-within-the-pipeline) to an OpenTelemetry metric type:

| Mezmo metric `value` type | Sent as |
| ---- | ---- |
| `gauge` | Gauge |
| `counter` | Monotonic sum |
| `set` | Gauge that holds the number of values in the set |
| `distribution` | Histogram, after the samples are grouped into buckets |
| `histogram` | Histogram |
| `summary` | A gauge named `<name>` with one data point per percentile, plus monotonic sums named `<name>_sum` and `<name>_count` |
| `sketch` | Not sent |

These details apply to the conversion:

- Each percentile data point of a summary has a `quantile` attribute that holds the percentile as a string, for example `"0.99"`. Summaries from the OpenTelemetry source are sent the same way.
- When a metric doesn't say whether it's delta or cumulative, the Destination decides from the metric's `kind`. `incremental` metrics are sent as delta and `absolute` metrics as cumulative.
- The `tags` of a Mezmo metric are sent as attributes on each of its data points. When a tag has the same key as an attribute in the event's metadata, the metadata value is sent.
- A metric with no timestamp is sent with the current time.
- When the Destination drops a `sketch` metric, it reports an error that names the type. The rest of the batch is still sent.

## Configuration

You can configure the Destination using these options.

### Configuration Options

| Option | Description | 
| ---- | ---- | 
| Collector Endpoint | The OpenTelemetry Collector URL that receives the data. Only http protocol is supported. No paths `/v1/logs` `/v1/metrics` `/v1/traces` needed, they will be added automatically based on a data type detected by the Destination. | 
| End-to-end acknowledgement | Enable this option to receive verification that OpenTelemetry data is being received by OTLP collector. | 
| Strategy | The authentication strategy to use. | 
| HTTP Headers | Additional headers to be sent with a request. The most common case is to set a secret key to authorize a request.\n\n**Note**: Authorization header is prohibited in case if some strategy has been already set up. | 
| Compression | Compression option: `none` or `gzip` to reduce network traffic |

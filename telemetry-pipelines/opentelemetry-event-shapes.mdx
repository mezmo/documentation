---
title: "OpenTelemetry event shapes"
description: "How log, metric, and trace events from the OpenTelemetry source differ from the deprecated per-signal OpenTelemetry sources"
---

The **OpenTelemetry** source takes in logs, metrics, and traces, and has a separate output for each: **Logs**, **Metrics**, and **Traces**. It replaces three deprecated sources: **OpenTelemetry Logs**, **OpenTelemetry Metrics**, and **OpenTelemetry Traces**.

The events the new source emits are shaped differently from those of the deprecated sources:

- **The deprecated sources** convert each OpenTelemetry record into a Mezmo-specific event. The main payload (log body, metric, or span) goes in `message`, and the OpenTelemetry context (resource, scope, attributes) goes in `metadata`.
- **The OpenTelemetry source** passes each record through in its original OpenTelemetry JSON form. Everything, including the resource and scope, is inside `message`.

<Warning>
Processors and destinations built for the deprecated sources won't work with the OpenTelemetry source's outputs unless you update their field paths or remap the events first.
</Warning>

## At a glance

| | Deprecated sources | OpenTelemetry source |
|---|---|---|
| **Sources** | One source per signal | One source with **Logs**, **Metrics**, and **Traces** outputs |
| **`message`** | The signal payload: log body string, Mezmo metric, or span | An envelope: `{ type, resource, scope, record }` |
| **Resource and scope** | `metadata.resource`, `metadata.scope` | `message.resource`, `message.scope` |
| **Record attributes** | `metadata.attributes` (metrics: also merged into `message.tags`) | `message.record.attributes` (metrics: `message.record.dataPoint.attributes`) |
| **Field naming** | snake case (`span_id`, `observed_timestamp`) | OpenTelemetry JSON camel case (`spanId`, `observedTimeUnixNano`) |
| **Times** | ISO 8601 strings | Nanoseconds since the Unix epoch, as strings |
| **Numeric values** | Numbers | Often strings (metric values, many attribute values) |
| **`metadata`** | OpenTelemetry context | Request metadata only, if present |
| **`annotations`** | Logs: `app`, `host`, `level`. Metrics and traces: none | `app` and `host` for all three signals |
| **Event `timestamp`** | Record time | Record time (the same) |

## The OpenTelemetry source envelope

All three outputs share the same envelope. `message.type` is `log`, `metric`, or `trace`, and `message.record` holds the signal-specific fields:

```json
{
  "message": {
    "type": "log | metric | trace",
    "resource": { "attributes": { "service.name": "...", "...": "..." } },
    "scope": { "name": "...", "version": "...", "attributes": {} },
    "record": { }
  },
  "annotations": {
    "app": "...",
    "host": "..."
  },
  "timestamp": "..."
}
```

- `annotations.app` is set from the `service.name` resource attribute, or `k8s.container.name` if that isn't set.
- `annotations.host` is set from the `k8s.pod.name` resource attribute, or `host.name` if that isn't set.
- `timestamp` is set from the record's time:

| Signal | `timestamp` source |
|---|---|
| Logs | `record.timeUnixNano`, falling back to `record.observedTimeUnixNano` when the time is missing or zero |
| Metrics | `record.dataPoint.timeUnixNano` |
| Traces | `record.startTimeUnixNano` |

| | Deprecated | OpenTelemetry |
|---|---|---|
| **Log body** | `message` (a string) | `message.record.body` |
| **Severity** | `metadata.severity_text`, `metadata.severity_number`, `metadata.level` | In `message.record` with OpenTelemetry JSON names, when the sender sets it |
| **Level annotation** | `annotations.level` | Not set |
| **Log attributes** | `metadata.attributes` | `message.record.attributes` |
| **Resource attributes** | `metadata.resource` (a flat map; no `attributes` wrapper) | `message.resource.attributes` |
| **Scope** | `metadata.scope` | `message.scope` |
| **Trace context** | `metadata.trace_id`, `metadata.span_id`, `metadata.flags` | In `message.record` with OpenTelemetry JSON names, when the sender sets it |
| **Times** | `metadata.time`, `metadata.observed_timestamp` (ISO 8601) | `message.record.timeUnixNano`, `message.record.observedTimeUnixNano` (nanosecond strings) |

<Note>
In the deprecated Logs source, `metadata.resource` holds resource attributes directly. In the deprecated Metrics and Traces sources, they're nested under `metadata.resource.attributes`. In the OpenTelemetry source, they're always at `message.resource.attributes`.
</Note>

### Log Records With an Empty Body

Some OpenTelemetry exporters, such as Codex, put all of a log record's data in its attributes and send no body. The OpenTelemetry source keeps these records and sets `message.record.body` to an empty string (`""`). If your processors match on the log body, also check `message.record.attributes` so these records aren't skipped.

The source drops a log record only when it has both an empty body and no attributes.

| | Deprecated | OpenTelemetry |
|---|---|---|
| **Event model** | Mezmo metric: `message.name`, `kind`, `tags`, `value` | OpenTelemetry metric and data point: `message.record.metric`, `message.record.dataPoint` |
| **Metric name** | `message.name`, normalized (for example, counters get a `_total` suffix) | `message.record.metric.name`, the original OpenTelemetry name |
| **Metric type** | `message.kind` (`incremental` / `absolute`) and `message.value.type` (`counter`, `gauge`, …) | `message.record.dataPoint.type` (`gauge`, `sum`, …) and `valueType`; no `kind` |
| **Value** | Number in `message.value.value` | String in `message.record.dataPoint.value` |
| **Description and unit** | `message.value.description`, `message.value.unit` | `message.record.metric.description`, `message.record.metric.unit` |
| **Labels** | `message.tags`: resource and data point attributes merged, snake_case keys | Kept separate in `message.resource.attributes` and `message.record.dataPoint.attributes`, original dotted keys |
| **Times** | `message.value.start_time_unix`, `time_unix` (ISO 8601) | `message.record.dataPoint.startTimeUnixNano`, `timeUnixNano` (nanosecond strings) |

<Note>
Which fields appear in `dataPoint` depends on the metric type. The example above is a gauge. Sums, histograms, and summaries can carry other fields.
</Note>

| | Deprecated | OpenTelemetry |
|---|---|---|
| **Span** | `message` | `message.record` |
| **IDs** | `message.trace_id`, `span_id`, `parent_span_id`, `trace_state` | `message.record.traceId`, `spanId`, `parentSpanId` (camel case; empty IDs may be left out) |
| **Times** | `message.start_timestamp`, `end_timestamp` (ISO 8601) | `message.record.startTimeUnixNano`, `endTimeUnixNano` (nanosecond strings) |
| **Span attributes** | `metadata.attributes`, with typed values (for example, `"http.status_code": 200`) | `message.record.attributes`; values may be strings (for example, `"http.status_code": "400"`) |
| **Resource and scope** | `metadata.resource.attributes`, `metadata.scope` | `message.resource.attributes`, `message.scope` |
| **Level** | `metadata.level` is `"trace"` | Not set; use `message.type == "trace"` |
| **Annotations** | None | `app`, `host` |
| **Dropped counts** | `message.dropped_attributes_count`, etc. | `message.record.droppedAttributesCount`, etc. |

## Migrating from the deprecated sources

When you replace the deprecated sources with the **OpenTelemetry** source:

1. Add one **OpenTelemetry** source, and connect each downstream processor to its **Logs**, **Metrics**, or **Traces** output.
2. Update the field paths your processors use, following the tables above. For example:
   - Logs: `message` becomes `message.record.body`
   - Metrics: `message.name` becomes `message.record.metric.name`
   - Traces: `message.trace_id` becomes `message.record.traceId`
   - All signals: `metadata.resource…` becomes `message.resource.attributes…`
3. Convert values before doing math or numeric comparisons: metric values, `*UnixNano` times, and many attribute values arrive as strings.
4. Check for anything that relies on fields the new source doesn't set, such as `annotations.level` on logs or `metadata.level` on traces.
5. If a destination expects Mezmo metric events, add a processor that remaps the OpenTelemetry metric fields to the Mezmo metric format first.
